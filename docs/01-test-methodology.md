# 测试方法与执行规程

编制日期：2026-10-24（Asia/Singapore）。主要现场执行日期：2026-10-23。目标：[jettt.me](https://jettt.me/)。

## 1. 方法定位与依据

本次采用浏览器驱动的手工/探索式黑盒测试，由浏览器自动化辅助导航、输入、截图及可访问性树/只读DOM观察。没有读取应用源代码、数据库、服务端日志、认证令牌或隐藏运行时状态，也没有开展接口扫描或压力测试。

期望结果来源于：页面明确承诺、用户提供的岗位清单、基本金额与数量算术、跨页面同日期/同范围的一致性。尚未获得完整需求规格、版本号和批准的权限矩阵。推定规则会在缺陷中明确标注，不将猜测的实现根因写成结论。

本仓库用例是依据现场记录回溯整理并补齐后续设计的用例集；不是81个用例均已完整执行的自动化套件。

## 2. 风险驱动的检查顺序

1. 收银称重、促销会员计价、现金找零和过期商品提示。
2. 商品详情等关键导航、角色授权可读性和岗位配置。
3. 总览/报表日期口径、库存身份维度、补货数量及单位。
4. 采购/收货/盘点/报损的表单和可追溯信息。
5. 会员与供应商页面、快捷键、键盘/读屏语义、窄屏布局。

## 5. 操作和判定规程

1. 记录目标地址、角色、日期、视口、前置夹具和原始临时状态。
2. 只通过页面可见入口和已观察的业务地址操作。登录验证码只在获得当次操作授权后识别提交；未绕过校验。
3. 等待真实数据加载完成。瞬时空表、旧可访问性树或旧画面不直接判为故障。
4. 数量输入优先逐键输入并移出焦点，核对数量框、行额和汇总；自动填入异常要用逐键输入复核。
5. 复现失败断言，记录期望、实际、角色、路由及证据；同一原因或同一主问题的多个失败用例去重到一个缺陷。
6. 取消本次表单，清除本次购物车行及搜索输入，恢复原现金实点。核对未提交订单、审批、收货、报损或付款。
7. 区分观察事实与推断。额外店长角色是配置差异；“本人单有审核按钮”不能证明服务端允许自审。

自动填入数字时曾观察到数量与金额不同步，逐键输入后采购与报损均正确。未把这一操作方式相关现象计入主要缺陷。

## 7. 修复与回归流程

缺陷记录→负责人确认期望/角色配置→分配修复→记录构建版本→以同夹具重测→扩展相邻场景→更新状态。当前没有修复构建或修复回归，状态不得写为已关闭。

回归至少覆盖：称重确认取消与小数精度；过期加购及隔离环境最终拦截；角色菜单/按钮/路由/服务端的一致性；报表日期与范围；单位换算与达到目标库存；报损明细与单位；键盘焦点和390px布局。
